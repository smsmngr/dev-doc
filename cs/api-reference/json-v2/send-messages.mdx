`POST /messages` přijímá pole objektů zpráv v jednom HTTP volání, což je efektivnější než opakované volání `POST /message`. Každý objekt v poli má stejné schéma jako jeden požadavek `/message` — v jedné dávce můžete kombinovat kanály, plány a payloady napříč objekty. Klíčový rozdíl oproti `/message` je, že odpověď vrací `message_id` na objekt požadavku, nikoli na jednotlivého příjemce; pro odvození ID jednotlivých příjemců připojíte index příjemce k `message_id`.

## Endpoint

```text
POST https://api.smsmngr.com/v2/messages
```

## Autentizace

API klíč předejte v hlavičce požadavku `x-api-key`:

```http
x-api-key: YOUR_API_KEY
```

## Tělo požadavku

Tělo požadavku je JSON pole obsahující 1–10 objektů zpráv. Každý objekt má strukturu shodnou s tělem požadavku `POST /message`.

<ParamField body="[n].body" type="string" required>
  Text zprávy pro tento objekt (až 1000 znaků). Vyžadováno, pokud všechny kanály v poli `flow` daného objektu nedefinují vlastní `body`.
</ParamField>

<ParamField body="[n].to" type="array" required>
  Seznam 1–10 objektů příjemců pro tuto zprávu. Každá položka vyžaduje řetězec `phone_number` v mezinárodním formátu E.164 (bez úvodního `+` nebo `00`).
</ParamField>

<ParamField body="[n].flow" type="array">
  Uspořádaný seznam objektů kanálů (`sms`, `viber`, `whatsapp_text`, `whatsapp_template`). SmsManager zkouší každý kanál v pořadí. Kompletní referenci polí kanálů naleznete v [POST /message](/cs/api-reference/json-v2/send-message#flow-channel-fields).
</ParamField>

<ParamField body="[n].callback" type="string">
  Webhook URL pro notifikace o doručení pro tento konkrétní objekt zprávy.
</ParamField>

<ParamField body="[n].tag" default="promotional" type="string">
  Štítek zprávy. Vestavěné hodnoty: `promotional`, `transactional`, `priority`. Přijímány jsou i vlastní řetězce.
</ParamField>

<ParamField body="[n].datetime" type="string">
  Naplánovaný čas odeslání v UTC ve formátu ISO 8601, např. `2025-06-01T09:00:00Z`.
</ParamField>

<ParamField body="[n].delivery_time" type="object">
  Omezení doručovacího okna s `days`, `start` (HH:MM), `end` (HH:MM) a `tz` (IANA timezone).
</ParamField>

<ParamField body="[n].payload" type="object">
  Libovolná data klíč-hodnota, která budou vrácena v událostech webhooku pro tento objekt zprávy.
</ParamField>

<ParamField body="[n].params" type="object">
  Parametry speciálního zpracování (např. zkracování odkazů). Podrobnosti získáte od podpory SmsManageru.
</ParamField>

## Limity

| Limit | Hodnota |
| --- | --- |
| Maximum objektů zpráv na požadavek | 10 |
| Maximum příjemců na objekt zprávy | 10 |
| Maximum celkových příjemců na API volání | 100 |

## Odpověď

Úspěšná odpověď `200` vrací objekt `MessagesResponse`.

<ResponseField name="request_id" type="string">
  Unikátní identifikátor tohoto API volání.
</ResponseField>

<ResponseField name="accepted" type="array">
  Objekty zpráv, které byly přijaty.

  <Expandable title="Pole přijaté položky">
    <ResponseField name="key" type="string">
      Nulově indexovaná pozice přijatého objektu zprávy ve vašem poli požadavku (např. `"0"` pro první objekt, `"1"` pro druhý).
    </ResponseField>

    <ResponseField name="message_id" type="string">
      Unikátní identifikátor pro tento objekt zprávy. Toto ID pokrývá všechny příjemce v rámci objektu — **není** na jednoho příjemce. Níže viz jak odvodit ID jednotlivých příjemců.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="rejected" type="array">
  Objekty zpráv, které byly odmítnuty.

  <Expandable title="Pole odmítnuté položky">
    <ResponseField name="key" type="string">
      Nulově indexovaná pozice odmítnutého objektu zprávy ve vašem poli požadavku.
    </ResponseField>
  </Expandable>
</ResponseField>

## Získání message\_id na jednotlivé příjemce

Když použijete `/messages`, SmsManager přiřadí jedno `message_id` na objekt požadavku, nikoli na příjemce. Pro identifikaci zprávy konkrétního příjemce — například při korelaci webhook událostí doručení — připojte `-<index_příjemce>` k `message_id` daného objektu.

Například, pokud první objekt v poli má dva příjemce a jeho `message_id` je `pppppppp-qqqq-rrrr-ssss-tttttttttttt`:

| Příjemce | Odvozené message\_id |
| --- | --- |
| `to[0]` (první příjemce) | `pppppppp-qqqq-rrrr-ssss-tttttttttttt-0` |
| `to[1]` (druhý příjemce) | `pppppppp-qqqq-rrrr-ssss-tttttttttttt-1` |

Události webhooku `sentMessage` budou obsahovat tato ID s příponou.

## Chybové odpovědi

| Status | Popis |
| --- | --- |
| `400 Bad Request` | Tělo požadavku je neplatné, překračuje limit velikosti pole nebo obsahuje objekt zprávy s chybějícími povinnými poli. Tělo odpovědi obsahuje řetězec `Message` s podrobnostmi. Ověřte, že tělo je platné JSON pole s 1–10 položkami a že každý objekt má alespoň `body` a `to`. |
