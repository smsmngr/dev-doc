Poté, co váš uživatel obdrží SMS a zadá 6místný kód, odešlete tento kód na tento endpoint. Úspěšná odpověď potvrzuje, že telefonní číslo patří uživateli, a vrací ověřené telefonní číslo spolu s volitelným HMAC `proof`, který můžete použít pro offline ověřování na vašem backendu.

## Endpoint

```text
POST https://verify-api.smsmanager.com/v1/validations/{token}/verify
```

## Autentizace

Zahrňte váš API klíč v hlavičce `X-API-Key`.

```http
X-API-Key: <your-api-key>
```

## Parametr cesty

<ParamField path="token" type="string" required>
  Validační token vrácený `POST /v1/validations` při zahájení validační session.
</ParamField>

## Tělo požadavku

<ParamField body="code" type="string" required>
  6místný kód, který uživatel zadal ze své SMS. Musí odpovídat `^[0-9]{6}$`.
</ParamField>

## Pole odpovědi

<ResponseField name="verified" type="boolean">
  `true`, když kód souhlasil a telefonní číslo je potvrzeno. `false`, pokud byl kód špatný, ale pokusy ještě zbývají.
</ResponseField>

<ResponseField name="phoneNumber" type="string">
  Ověřené telefonní číslo. Přítomné pouze když je `verified` `true`.
</ResponseField>

<ResponseField name="token" type="string">
  Validační token pro tuto session. Přítomný pouze když je `verified` `true`.
</ResponseField>

<ResponseField name="code" type="string">
  Kód, který byl úspěšně ověřen. Přítomný pouze když je `verified` `true`.
</ResponseField>

<ResponseField name="timestamp" type="string (ISO 8601)">
  UTC timestamp z okamžiku, kdy byla validace zahájena. Použijte tuto hodnotu spolu s `phoneNumber`, `token`, `code` a `proof`, pokud chcete ověřit HMAC proof offline. Přítomný pouze když je `verified` `true`.
</ResponseField>

<ResponseField name="proof" type="string">
  HMAC proof, který kryptograficky sváže `phoneNumber`, `token`, `code` a `timestamp`. Přítomný pouze když je `verified` `true` **a** váš účet má nakonfigurován `verificationSecret`. Předejte jej na `POST /v1/verify-proof` pro offline ověření.
</ResponseField>

<ResponseField name="verifiedAt" type="string (ISO 8601)">
  UTC timestamp, kdy byl kód přijat. Přítomný pouze když je `verified` `true`.
</ResponseField>

## Limity pokusů

Ve výchozím nastavení každá validační session povoluje až **6 pokusů o ověření**. Každý neuspěšný pokus snižuje počítadlo vrácené v poli `attemptsRemaining` chybové odpovědi. Když počítadlo dosáhne nuly, session je uzamčena a jakýkoli další pokus vrací odpověď `429`. Pokud uživatel potřebuje zkusit znovu, zahájte novou validační session přes `POST /v1/validations`.

## Chybové odpovědi

| HTTP status | Kód chyby | Podmínka |
| --- | --- | --- |
| `400` | — | Kód byl špatný; pokusy zbývají — `{ "message": "Invalid code", "attemptsRemaining": 3 }` |
| `400` | — | Validační session vypršela (\>10 min) — `{ "message": "Validation expired" }` |
| `401` | `MISSING_API_KEY` | Hlavička `X-API-Key` nebyla přítomna v požadavku. |
| `401` | `INVALID_API_KEY` | Poskytnutý API klíč je neplatný nebo byl deaktivován. |
| `404` | — | Žádná session nenalezena pro dodaný `token` — `{ "message": "Validation not found" }` |
| `429` | — | Všechny pokusy vyčerpány — `{ "message": "Too many attempts" }` |
