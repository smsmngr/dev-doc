HMAC proof vám umožňuje potvrdit, že validace telefonního čísla byla skutečně dokončena SmsManagerem — bez autentizovaného API volání a bez toho, aby váš backend musel držet API klíč. To je ideální pro mikroslužby, edge funkce nebo jakoukoli službu, která přijímá ověřovací data přeposlaná od klienta, ale neměla by jim slepě věřit.

## Co je HMAC proof?

Když má váš účet nakonfigurován `verificationSecret`, Verify API připojuje pole `proof` ke každé validační a ověřovací odpovědi. Tento proof je HMAC podpis vypočítaný z polí `phoneNumber`, `token`, `code` a `timestamp` pomocí vašeho tajemství. Protože tajemství zná pouze SmsManager a váš backend, platný proof zaručuje, že data pocházejí ze skutečné validační session.

Proof ověříte zasláním čtyř původních polí plus samotného proof na tento endpoint. SmsManager znovu vypočítá HMAC na serveru a řekne vám, jestli souhlasí — API klíč není potřeba.

## Endpoint

```text
POST https://verify-api.smsmanager.com/v1/verify-proof
```

## Autentizace

**Nevyžaduje autentizaci.** HMAC proof je credentiál. Kdokoli, kdo má čtyři data pole a proof, může tento endpoint zavolat, takže zacházejte s proof daty jako s citlivými při přenosu.

## Tělo požadavku

<ParamField body="phoneNumber" type="string" required>
  Telefonní číslo přesně tak, jak bylo vráceno v ověřovací odpovědi (pouze číslice, s kódem země).
</ParamField>

<ParamField body="token" type="string" required>
  Validační token z původní odpovědi `POST /v1/validations`.
</ParamField>

<ParamField body="code" type="string" required>
  6místný kód, který byl ověřen, jak byl vrácen v odpovědi `POST /v1/validations/{token}/verify`.
</ParamField>

<ParamField body="timestamp" type="string (ISO 8601)" required>
  UTC timestamp z okamžiku zahájení validační session, jak byl vrácen v odpovědi `POST /v1/validations`. Tato hodnota je součástí HMAC vstupu a musí přesně odpovídat.
</ParamField>

<ParamField body="proof" type="string" required>
  HMAC proof řetězec vrácený v ověřovací odpovědi (`POST /v1/validations/{token}/verify`).
</ParamField>

## Pole odpovědi

<ResponseField name="valid" type="boolean">
  `true`, pokud je proof autentický a čtyři vstupní pole odpovídají původně podepsaným datům. `false`, pokud bylo některé pole zmanipulováno nebo je proof špatný.
</ResponseField>

<ResponseField name="expired" type="boolean">
  Přítomný pouze když je `valid` `false`. Nastaven na `true`, když je samotný proof strukturálně platný, ale validační session je starší než 24 hodin. Použijte to k rozlišení skutečné (ale zastaralé) proof od zmanipulované.
</ResponseField>

## Chybové odpovědi

| HTTP status | Podmínka |
| --- | --- |
| `400` | Jedno nebo více povinných polí (`phoneNumber`, `token`, `code`, `timestamp`, `proof`) chybí v těle požadavku. |
| `400` | Váš účet nemá nakonfigurován `verificationSecret`, takže proofy nelze generovat ani ověřovat. |

## Vypršení proof

Proofy jsou platné po dobu **24 hodin** od `timestamp` validační session. Po tomto okně tento endpoint vrací `{ "valid": false, "expired": true }`. Pokud potřebujete ověřit starší session, použijte autentizovaný endpoint `PATCH /v1/validations/{token}`, který kontroluje stav uložený na straně serveru spíše než ověřování HMAC lokálně.

## Alternativa: PATCH /v1/validations/{token}

Pokud váš backend již drží `token` a má přístup k vašemu API klíči, `PATCH /v1/validations/{token}` je jednodušší volba. Pošlete `proof` v těle požadavku a přímo obdržíte příznak `valid`, `phoneNumber` a timestamp `verifiedAt` z uložené session — není třeba předávat všechny čtyři HMAC vstupy.

```bash
curl -X PATCH \
  https://verify-api.smsmanager.com/v1/validations/<token> \
  -H "Content-Type: application/json" \
  -H "X-API-Key: <your-api-key>" \
  -d '{ "proof": "86dd8444ed76402c..." }'
```
