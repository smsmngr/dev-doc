Kredit se v SmsManageru odečítá **až v okamžiku odeslání** konkrétní zprávy. Neodečítá se při naplánování zprávy k odeslání ani ve chvíli, kdy zprávu připravíte v administraci. Tento princip je důležitý pro správné pochopení toho, kdy se stav vašeho účtu skutečně změní a proč lze odeslání naplánovat i bez dostatečného kreditu.

---

## Kdy se kredit odečítá

Kredit se strhává **v jediném okamžiku a to při odeslání zprávy**. Ve stejnou chvíli probíhá i závěrečná kontrola, že zprávu lze odeslat (např. že příjemce není na blacklistu nebo se neodhlásil z odběru).

Kredit se naopak **neodečítá**:

- **při naplánování odeslání** — zpráva s polem `datetime` do budoucna se zařadí bez ohledu na aktuální stav kreditu,
- **při přípravě zprávy v administraci** — dokud nedojde ke skutečnému odeslání, kredit zůstává nedotčen.

<Note>
  Protože se kredit rezervuje až při odeslání, **odeslání se naplánuje i tehdy, když v daný moment nemáte dostatek kreditu.** Kredit stačí doplnit kdykoli před okamžikem odeslání.
</Note>

---

## Kontrola kreditu při odeslání

Až ve chvíli odeslání SmsManager ověří, že máte na danou zprávu dostatek kreditu, a pokud ano, kredit odečte. Tehdy se také vyhodnotí ostatní pravidla pro odeslání (blacklist, opt-out apod.).

Výše odečteného kreditu se řídí cenou zprávy podle destinace, kanálu a počtu segmentů. Za co se u jednotlivých kanálů platí, popisuje koncept [Účtování zpráv podle kanálu](/concepts/message-billing). Podrobnosti o tom, jak SmsManager požadavek přijímá a následně zpracovává, najdete v konceptu [Příjem a zpracování požadavku](/concepts/request-acceptance).

<Note>
  Sdílené podřízené klíče (vytvořené se `shared: true`) čerpají kredit z peněženky nadřazeného klíče. `GET /credit` u nich proto vrací stav této sdílené peněženky.
</Note>

## Vaše cena pro destinaci

Kolik zaplatíte za zprávu na konkrétní číslo, zjistíte přes `POST /credit/price`. Endpoint vrací vaše skutečné ceny pro jedno cílové číslo, rozdělené podle kanálů. Ceny už zahrnují vaši dosaženou objemovou slevu. Proto mohou být nižší než obecný ceník z `GET /credit/prices`.

```bash Požadavek
curl -X POST https://rest-api.smsmngr.com/v1/credit/price \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"to": "420777123456"}'
```

```json Odpověď (výňatek)
{
  "success": true,
  "price": {
    "to": "420777123456",
    "normalized": "420777123456",
    "calling_code": "420",
    "currency": "czk",
    "prices": {
      "sms": {
        "default": { "mcc": 230, "price_czk": 0.92, "price_eur": 0.04 },
        "high": { "mcc": 230, "price_czk": 0.92, "price_eur": 0.04 },
        "lowcost": { "mcc": 230, "price_czk": 0.92, "price_eur": 0.04 },
        "direct": { "mcc": 230, "price_czk": 1.25, "price_eur": 0.05 }
      },
      "viber": {
        "default": { "mcc": 230, "price_czk": 0.39, "price_eur": 0.016 }
      }
    }
  }
}
```

- `prices` je klíčované kanálem: `sms`, `viber`, `whatsapp_text`, `whatsapp_template` a `rcs`.
- `sms` obsahuje jednu položku pro každou gateway (například `high`, `lowcost` nebo `direct`) a navíc `default`, který je kopií `high`.
- Ostatní kanály obsahují jen `default`.
- Kanály, které do dané destinace nedoručují, v `prices` chybí.
- `price_czk` a `price_eur` jsou ceny za jednu část zprávy.

Volitelným polem `platform` omezíte odpověď na jeden kanál, například `"platform": "sms"`. Číslo v `to` můžete poslat i v jiném než mezinárodním formátu. Pole `normalized` pak obsahuje číslo převedené na mezinárodní formát.

## Nedostatek kreditu — chyba 307

Pokud v okamžiku odeslání není na účtu dostatek kreditu, zpráva je **odmítnuta s chybou `[307] Insufficient credit`**. Zpráva skončí ve stavu `rejected` a informaci obdržíte na vaší callback URL:

```json Webhook událost (výňatek)
{
  "message_id": "e27ff0ac-87b5-4e1d-b644-5fc6029e2a11",
  "result": "rejected",
  "result_info": "[307] Insufficient credit"
}
```

<Warning>
  **Odeslání se po chybě 307 už znovu neopakuje.** Zpráva zůstane trvale ve stavu `rejected` — doplnění kreditu ji automaticky znovu neodešle. Chcete-li ji doručit, po dobití kreditu ji odešlete znovu jako nový požadavek.
</Warning>

## Praktický důsledek pro vaši integraci

- **Naplánování nezaručuje odeslání.** I naplánovanou zprávu je potřeba pokrýt kreditem až do okamžiku jejího odeslání.
- **Hlídejte si stav kreditu.** Zejména u odesílání naplánovaného na budoucnost zajistěte dostatek kreditu před daným časem.
- **Zpracujte stav `rejected` s kódem 307.** Naslouchejte na callback URL a v poli `result_info` rozlišujte `[307] Insufficient credit` od ostatních příčin zamítnutí. Zamítnuté zprávy po dobití kreditu v případě potřeby odešlete znovu.

<Tip>
  Aktuální stav kreditu i automatická upozornění na jeho vyčerpání lze sledovat přes REST API v sekci [Kredit](/api-reference/rest/overview). AI asistent připojený přes [MCP server](/ai/mcp-server) zjistí zůstatek nástrojem `get_credit` a připraví podklady pro dobití převodem (`get_topup_details`).
</Tip>
